# Meter Gomoku —— 连线版

[English](README.md) | **中文**

Windows 桌面端五子棋 / 连珠助手。它会**直接读你正在对弈的那盘棋**——任何第三方客户端、网页棋盘或模拟器都行——把局面同步到内部小棋盘，交给随包的 Rapfi 引擎思考，必要时替你落子。本仓库是**连线（识图）版**：屏幕取像 + 置顶小窗 + 模拟点击，不接触对方程序的任何内部接口。

![主界面](docs/images/main.png)

> 📄 **可打印的双语说明（PDF，48 页）：** [docs/Meter-Gomoku-Manual.pdf](docs/Meter-Gomoku-Manual.pdf)

## 一、它和别的辅助有什么不同

| | |
|---|---|
| **通吃任何客户端** | 不做注入、不读内存，只做两件事：屏幕取像、模拟点击 |
| **锁定几何的识别** | 15×15 网格只找一次并**锁定**；之后只重读发生变化的交点——画面静止几乎零开销，落一子只重读一格 |
| **置顶连线小窗** | 固定 304×712，永远压在对局窗之上；控制面板、状态区、局面小棋盘都在里面 |
| **真引擎** | Rapfi（GPL-3.0）以独立进程运行，随包四种指令集变体；主车道独占整张置换表 |
| **官方平衡工具** | 平衡搜索走引擎原生**成对** `YXBALANCETWO`；交换开局用官方开局库，不是手搓的表 |
| **运行期零依赖** | 不需要 Python、Node 或额外 DLL；唯一运行时依赖是 WebView2（Win11 自带） |

## 二、快速上手

1. 运行 `Release/Meter Gomoku_Setup4.42.exe` 完成安装。
2. 打开程序，再打开你的五子棋客户端（或网页棋盘），进到对局画面。
3. 主界面顶栏点 **连线**，弹出小窗。
4. 点 **框选棋盘**，把棋盘**连外框一起**框进去。
5. 选 **AI 执黑 / AI 执白**、规则与思考时间，再打开 **自动落子**。

连线窗里的小棋盘会立刻跟着走。如果你的客户端不认模拟点击，打开 **真实点击**（会借用物理光标，见第五节）。

## 三、主界面

![主界面](docs/images/main.png)

| 区域 | 内容 |
|---|---|
| **顶栏** | 连线（打开连线窗）· 识图 · 复盘 · 历史 · 关于 · EN/中（语言）· 颜色 |
| **左栏** | 引擎仪表盘（深度 / 速度 / 节点 / 用时 / 评估 / 最佳）与评估曲线（黑白两条，纵轴按分数自动进位，最大约 ±1200） |
| **棋盘** | 15×15，四边带坐标，正中一颗「继续 / 暂停」键；所有分析标记都直接画在棋盘上 |
| **右栏** | 卡片：对局设置、计算评估、引擎仪表盘。标题栏可拖动换位、点小横杠折叠、点 ✕ 关闭；布局自动记忆 |
| **底栏** | 分析计算 · ◀ ▶（逐手）· 重新开始 · 保存局面 · 撤销 / 重做 / 交换黑白 · AI 执子 · 设置（添加卡片） |

### 对局设置

![对局设置卡](docs/images/setup.png)

* **模式** —— 对弈 / 摆盘 / 残局。
* **AI 执子** —— 黑 / 白；两个都不开就是你自己下两边。
* **思考时间** —— 0.2 ~ 300 秒，与连线窗**同一个口径**，两边始终一致。
* **规则** —— 无禁手 / 无禁手 · 长连不赢 / 连珠（有禁手）。
* **引擎** —— 线程数与哈希表。线程上限按本机真实拓扑算（物理核留两核给识别和系统），哈希按可用内存自适应；两项都会持久化，下次打开照旧。
* **棋盘显示** —— 棋子上标手数、悬停预览框。
* **局面代码** —— 复制 / 粘贴 / 载入，一整串字符串就是整盘棋。

### 计算评估

![计算评估卡](docs/images/analysis.png)

| 功能 | 作用 |
|---|---|
| **计算** | 对当前局面单路深搜，最佳点标在棋盘上；再点一次变「停止计算」 |
| **多点分析** | 按「分析点数」（2~8，默认 4）给出若干候选，每个圆圈里是名次与评估分 |
| **平衡点** | 走引擎原生**成对**平衡搜索，给出黑白双方都没有明显优势的点，并报出平衡引擎自己的评估分。`\|评估\| ≤ 50` 才算官方平衡窗口内的「平」（ScalingFactor = 200，胜率 = sigmoid(评估/200)） |
| **点数** | 平衡点给几个（1~6）。空盘固定 3 个——黑 1 天元，白 2 与黑 3 由一次成对搜索联合给出 |
| **扫描防守** | 在 9×9 邻域逐个空点打分：**W = 距赢几步、L = 距输几步**，徽标颜色由青到红连续渐变；落子后自动重扫 |
| **前瞻 / VCF / VCT** | 强制线工具。前瞻一路推演到真的五连；VCF 只走连续冲四；VCT 再加上活三 |
| **教练** | 轮到你时用方形四色提示（最佳 / 良好 / 一般 / 劣势），一落子就消失 |
| **分析计算** | 后台持续深算并铺出引擎当期榜单；落子 / 悔棋自动重开会话 |
| **清除标记** | 一键擦掉本卡留在棋盘上的全部标记，不动局面本身 |

### 引擎仪表盘

![引擎仪表盘](docs/images/engine.png)

`深度` · `速度`（节点/秒） · `节点` · `用时`（分析计算模式下跨轮累加） · `评估`（正数对行棋方有利） · `最佳`。任何计算期间这些数值都会边算边跳，是判断「引擎有没有在干活」最快的地方。

## 四、识图

![识图窗](docs/images/vision.png)

顶栏点 **识图** 打开。它把一张截图变成局面代码。

1. **上传图片**（可多选，至多 150 张）或 **屏幕截图** 抓取屏幕区域。
2. **裁剪** —— 选框自动贴住棋盘并向外多留约棋盘 1/30 的余量，保证最外侧棋子完整。
3. **识别** —— 结果同步成局面代码，可复制，也可直接载入练习。
4. **修改** —— 交换黑白（点一黑一白即互换）、删子、补黑 / 补白；`Ctrl+Z` 撤销。
5. **VC 模式** —— 算杀题专用：黑白子数可以不等、补子不限量；载入后自动切成残局模式并预设进攻方。

**识别参数** 把 6 项阈值直接摊在面板上，拖动即时生效：

| 参数 | 含义 |
|---|---|
| 同步时间间隔(ms) | 每拍读子的间隔。调小更跟手，但更占 CPU |
| 灰度偏差(0-255) | 判定「这里有棋子」的灰度门限 |
| 黑色偏差 / 黑色占比 | 黑子的灰度门限与格内占比。黑子识别过多 → 调小；漏识 → 调大 |
| 白色偏差 / 白色占比 | 同上，针对白子 |

### 识别是怎么做的

* **两级融合** —— 首帧由软件自带识别定型（同时给出 15 条横线与 15 条竖线的精确位置）；锁定后交给引擎的同步读子，交接时把窗口指纹一起递过去，所以全盘只搜一次。
* **逐格变化识别** —— 每个交点留一份 6×6 采样签名，静止时 0 格重读、落一子只重读 1 格。
* **图片适应性** —— 整盘读空时先按本帧峰值放松阈值；仍为空就换**局部对比**读子（只比交点中心与外圈对角小块的亮度差，深色盘、浅色盘一视同仁）；网格与线条没对上时请旧识别器复核，谁更合理用谁；整行 15 格同色会判为错位一格并自动平移重读。
* **防误读** —— 软件自己画的标记全部排除出屏幕捕获，绝不会把自己的覆盖层当成棋子。

## 五、连线模式

![连线窗](docs/images/link.png)

连线窗是独立的顶层窗口，304×712，永远置顶。识别与 AI 的全部工作都在这里；主窗只做同步显示。

| 控件 | 作用 |
|---|---|
| **规则三键** | 无禁手 / 长连不赢 / 有禁手——直接切换连线窗使用的终局与禁手判定 |
| **框选棋盘** | 在屏幕上拖一个矩形框住棋盘；框完成后开始识别 |
| **识别参数** | 把这块按键区就地换成 6 项阈值，边拖边生效（见第六节） |
| **真实点击** | 用物理鼠标点击。**默认关闭**——只有「只认真实鼠标」的客户端才需要，打开期间会占用光标 |
| **自动落子** | 识别到对方落子即思考，并替你落子 |
| **×1 / ×2 / ×3** | 每个落点连点几下 |
| **AI 执黑 / AI 执白** | 互斥，选中会立刻同步到主窗 |
| **思考时间** | 0.2 ~ 300 秒，与主窗共用同一个值 |
| **交换平衡点** | 开局平衡点（见下） |
| **交换评估** | 与平衡点相互独立：用**对弈引擎**给当前交换局面打分，帮你判断值不值得交换 |
| **取消** | 中止在途的平衡 / 评估计算，并清掉已经画出的标记 |

### 状态区

`深度` · `速度` · `节点` · `评估` 实时刷新；下面是定高的虚线文本框，说明当前在做什么（识别中 / 思考中 / 已标出平衡点……）。右侧小棋盘实时镜像识别结果并显示子数——某一帧什么都没读到时，它保持上一手的好盘面，不会无故清空。

### 自动落子：三级管线

| 级 | 方式 | 何时用 |
|---|---|---|
| 一级 | `PostMessage` 直达目标窗口 | 默认首选：最轻，不干扰物理鼠标 |
| 二级 | `SendInput` | 下一帧判定一级没生效时自动升级 |
| 三级 | `SetCursorPos` + `mouse_event`（真实点击） | 前两级都无效时兜底；一旦生效就钉住复用 |

每一级都用下一帧判断是否真的落下。三级全失效不会死等：自动重开一整轮，最多 3 轮，之后才停机提示。一局结束（五连）会自动关闭自动落子，下一局重新打开即可。

### 交换平衡点

**空盘**走官方开局库：引擎按当前规则给出三手开局（无禁手用 Swap2 库、有禁手用 RIF 库），再用棋盘八种对称变换展开去重。随后让平衡引擎给这一对打分——那个分就是你能核对的数。

| 盘面手数 | 点数 | 颜色 | 说明 |
|---|---|---|---|
| 0 手（空盘） | 3 点 | 两黑一白 | 黑 1 固定天元，白 2 / 黑 3 来自官方开局库 |
| 3 子（共 5 手） | 2 点 | 一黑一白 | 一次**成对**平衡搜索同时给出这两个点 |
| 超过 5 子 | — | — | 已过交换窗口，软件会明示 |

标记画在识别框内的交点上：蓝 / 紫圈加序号表示落子顺序，你把这几个子下完，标记自动消失。点「交换平衡点」会顺带取消已选的 AI 执子（两者相互干扰）；若自动落子已开，则按序自动摆完。

## 六、连线窗里的识别参数

![识别参数](docs/images/link-params.png)

点一下就把按键区换成 6 项阈值，统计行腾空，下方文本框改成逐条参数说明。

* 拖动或输入**立即生效**并同时落盘，下次启动还是这套值。
* **通用** 一键载入默认值（200 / 50 / 96 / 33 / 96 / 33），能识别绝大部分棋盘。
* **存档 / 读档** 把当前 6 项按主题名存起来（最多 50 个，抽屉里可加载 / 全选 / 删除 / 撤销）。
* **应用** 保存并收起参数区；**取消** 把 6 项还原成上次已应用的值（页面与宿主两侧一起还原）。

## 七、规则与禁手

| 规则 | 五连 | 禁手 |
|---|---|---|
| 无禁手 | 连五即胜，长连也算 | 无 |
| 无禁手 · 长连不赢 | 连五即胜；**六连及以上不算赢** | 无 |
| 连珠（有禁手） | 连五即胜 | 长连、四四、三三（四三是合法的） |

## 八、性能说明

* 引擎跑在**独立进程**，且**绝不钉核**——在混合架构 CPU 上钉核会让节点/秒掉到五分之一。
* 识别独占一部分核心并以高优先级运行；它是间歇性的（逐格变化识别），实际占用很小。
* 引擎主车道独占整张置换表，其余车道降到地板值，总占用恒等于你选的档位。
* 首次启动默认取线程列表的最大值（16 线程机器上是 12 线程 / 512 MB）。

## 九、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 找到棋盘但一颗子都没有 | 框太紧，或棋子与棋盘对比度太低 | 把棋盘**连外框**重新框一次；再把黑色 / 白色偏差调小试试 |
| 某一色子多读或少读 | 阈值不适配这个主题 | 进「识别参数」：偏差管灰度门限，占比管格内覆盖 |
| 自动落子不动 | 客户端只认真实鼠标输入 | 打开**真实点击**；并保持窗口位置不动（框是几何锁定的） |
| 一开就白屏 | 安全软件把 UI 包隔离了 | 把安装目录加白名单后重装 |
| 360 报毒 | 未签名的截屏类程序 | 允许运行，或对构建做代码签名 |
| 小棋盘不跟着走了 | 棋盘被挪动，或窗口被缩放 | 重新点**框选棋盘** |

## 十、目录结构

```
host/      Win32 C++ 宿主：棋盘扫描、识别 IPC、引擎进程、覆盖层窗口、模拟点击
           （host.cpp、engine_host.*、appver.*）
ui/        WebView2 前端：calc.html / calc.css / calc.js / bridge.js
vision/    屏幕棋盘 / 棋子识别（静态链接 OpenCV）
core/      旧的共享引擎胶水，仅作参考保留（4.42 前端已不加载）
rapfi/     Rapfi 搜索核心 + 各指令集构建预设（上游：dhbloo/rapfi）
Release/   预编译安装包（Meter Gomoku_Setup4.42.exe）
docs/      本文档使用的截图
```

> `ui/` 是发货版 4.42 前端的**阅读用快照**，不是完整构建树（引擎适配层与少量辅助模块未收录）。构建脚本、UI 打包工具与中间产物按设计不入库。

安装包里的 UI 是**单一容器** `calc/ui.pak`（二进制加密），宿主在内存里解密后交给 WebView2，磁盘上没有明文 HTML。

## 十二、从源码构建（参考）

工具链：MSVC 2022 (v143)、Windows 10/11 SDK、WebView2 SDK、静态 OpenCV。
